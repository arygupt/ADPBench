Methodology

Numbers you can replay.

Every score on this site comes from a frozen run record: the submission hash, netlist hash, case manifest, tool versions, and git commit are stored alongside it, and adpbench replay re-scores the frozen file to verify the published number.

The metric

A submission is synthesized to a gate netlist with a pinned Yosys flow (synth -noabc) and simulated at gate level with the same release's cell models. Area is a cell count — a proxy, not a placed-and-routed area. Time is cycles, measured from input presentation to the last accepted output across all transactions. 

adp   = cells × cycles
score = baseline_adp / submission_adp      // higher is better

What this is not. cells × cycles counts generic cells before ABC optimization. A 100 MHz testbench clock does not prove the netlist closes timing at 100 MHz, and no power is modeled. Treat the score as a reproducible proxy, not silicon sign-off.

The contract

  • Each input port has its own valid/ready pair and its own element count per transaction; streams of different lengths run independently.
  • Every case drives two back-to-back transactions without reset — leaked per-transaction state fails.
  • Correctness is exact integer equality on held-out random seeds plus directed edge cases (zeros, extreme signed values).
  • A protocol run applies forced output stalls and seeded input gaps: dropping or mutating a word while stalled fails, extra output words fail, and finishing without consuming all input beats fails.
  • Synthesis must reduce to gate-level internal cells; blackboxes and residual arithmetic cells ($mul, $div, …) are rejected, since the simulator would resolve them for the price of one cell.

The pipeline

submission.v
  → synthesize   yosys, pinned flow, chparam parameters      → netlist + cells
  → vectors      numpy golden model, held-out seeds          → inputs + expected
  → simulate     iverilog on the netlist (score + protocol)  → cycles, bit-exact pass/fail
  → score        baseline_adp / adp

Synthesis and simulation judge one artifact: the parameters applied at synthesis are the ones the testbench drives, and the simulated netlist is the netlist whose cells were counted.

The boundary

Agents run inside Docker on a pinned substrate image — Yosys built from the exact commit the host scores with, Icarus v13_0, same cell library. The container mounts the task directory read-write and a seed-redacted harness bundle read-only (held-out seeds are stripped; reference solutions are not shipped). After the run, nothing in the agent-writable directory is trusted: the submission is copied symlink-free to a host-only directory, hashed, and scored there. Fabricated records and symlink tricks are covered by regression tests.

Reporting

The headline is beat-baseline rate — the fraction of planned attempts that end correct and faster than the baseline. Correctness rate, geometric mean among successful attempts, infrastructure failures, timeouts, and repetitions are all disclosed; a correctness-gated average is never presented alone. Attempts are counted, not averaged away.

Current caveats

  • One attempt per cell (pilot-001); model variance is not yet sampled.
  • All five evaluated systems are free-tier OpenCode models; stronger systems are not on the board yet.
  • The dot-product sanity solution (2.89×) and the best model result (3.39×) suggest the ceiling is not yet known.
  • Four problems is a small sample of the operator space; conclusions should stay at "these models, these tasks".

Run it yourself

uv venv && uv pip install -e .
.venv/bin/python -m adpbench list
.venv/bin/python -m adpbench pilot --config pilot/pilot_free_models.json --jobs 4
.venv/bin/python -m adpbench report --runs runs/
.venv/bin/python -m adpbench replay runs/<pilot>/<model>/<problem>/rep1

Submissions are evaluated with adpbench run <problem> -f dut.v; the static site data regenerates with adpbench site sanity --out pilot/sanity.json and adpbench site export --pilot runs/<pilot> --out site/data --sanity pilot/sanity.json.
